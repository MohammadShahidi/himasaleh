# آزمایش سرتاسری فاز ۱ (API + دیتابیس واقعی)

این‌ها تست‌های واحد نیستند؛ یک API در حال اجرا با PostgreSQL و S3 واقعی را از اول تا آخر می‌رانند:
ثبت‌نام راننده ← مدارک ← بررسی کارشناس (رد، اصلاح، تأیید) ← پیامک‌ها ← بار آزمایشی ← قبول بار ← قدم‌های آفلاین ← تحویل ← کیف پول و دفتر کل، به‌علاوهٔ مالک متفاوت (لینک، ویدیو بدون ورود)، ثبت دستگاه و ack اعلان، و بستن مسیرهای غیرمجاز.

## اجرا

۱. دیتابیس و S3 (مثلاً با `docker compose -f infra/docker-compose.dev.yml up -d`) و مایگریشن‌ها (`prisma migrate deploy`).
۲. API با این تنظیمات: `SMS_PRIMARY_PROVIDER=fake`، `PUSH_PROVIDER=fake`، `ENABLE_DEV_TOOLS=true`، `S3_AUTO_CREATE_BUCKETS=true`، و خروجی‌اش در یک فایل لاگ (کد ورود از همان خوانده می‌شود).
۳. اجرا:

```bash
API_URL=http://localhost:4000 API_LOG=/مسیر/api.log PSQL="docker exec <نام-کانتینر-پستگرس> psql -U hm -d hm" node apps/api/test-e2e/phase1.mjs
```

`sms-fallback.mjs` را بعد از آن بزنید (حدود ۸۰ ثانیه): ثابت می‌کند پیامک بار جدید وقتی اعلان تأیید نشده باشد فقط بعد از مهلت می‌رود.

**روی دیتابیس تولید اجرا نکنید.** اسکریپت کاربر کارشناس و رانندگان آزمایشی می‌سازد و مستقیم با `psql` در دیتابیس می‌نویسد.

## کنسول آزمایش (روی سرور آزمایشی، بدون SQL)

`console.mjs` همان کاری را می‌کند که تستر روی سرور با کنسول و `/dev-otp` می‌کند و فقط HTTP می‌زند: ورود با شمارهٔ آزمایشی، تنظیمات، منقضی کردن پیشنهادها، لغو سفر، یادآوری، پاک‌سازی و مجوزها. نیاز: `ENABLE_DEV_TOOLS=true`، `SMS_TEST_PREFIX=0900000` و `STAFF_BOOTSTRAP_PHONES=09000000001`.

```bash
API_URL=https://himasaleh.ir node apps/api/test-e2e/console.mjs
```
