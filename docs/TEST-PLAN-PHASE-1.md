# سناریوهای تست فاز ۱ (راننده) — اجرا روی لوکال

> برای تستر. شاخه: `phase-1/driver` ([PR #9](https://github.com/MohammadShahidi/himasaleh/pull/9)). هر سناریو یک شناسه دارد؛ گزارش را با همان شناسه بنویسید.
> **بخش ۵ سناریوهای «آماده نیست» است**: چیزهایی که هنوز ورودی‌شان از مالک نرسیده (کلید و سرویس واقعی، اپ اندروید). سناریوها نوشته شده تا بعد از آماده شدن اجرا شوند؛ **الان آن‌ها را اجرا نکنید** و نتیجه‌شان را «ناموفق» ثبت نکنید.

> **دو حالت اجرا:** (الف) **لوکال** — بخش ۱ تا ۷ همان‌طور که نوشته شده. (ب) **روی سرور مستقر `https://himasaleh.ir`** — **اول بخش ۸ را بخوانید**: ریسک‌های داده و هزینه، پیش‌پرواز، نقش اپس، تغییر هر سناریو و سناریوهای مخصوص سرور. بخش ۱ و ۲.۴ فقط برای لوکال‌اند.

اولویت‌ها: **P1** باید جواب بدهد تا فاز تأیید شود · **P2** مهم · **P3** ظاهر و جزئیات.

## ۱. آماده‌سازی محیط لوکال

> فقط برای اجرای لوکال. روی سرور مستقر به بخش ۸ بروید.

پیش‌نیاز: Node ۲۴، pnpm، Docker.

```bash
git checkout phase-1/driver
pnpm install
pnpm dev:infra                                  # PostgreSQL و S3 (SeaweedFS) در Docker
cp apps/api/.env.example apps/api/.env
pnpm --filter @hm/shared build
pnpm --filter @hm/api dev:buckets
pnpm --filter @hm/api db:migrate                # همهٔ مایگریشن‌ها (باید «already in sync» یا اعمال موفق بدهد)
```

در `apps/api/.env` این‌ها را مطمئن شوید (بقیه پیش‌فرض می‌ماند):

```
SMS_PRIMARY_PROVIDER=fake
PUSH_PROVIDER=fake
SHAHKAR_PROVIDER=manual
ENABLE_DEV_TOOLS=true
```

اجرا (دو ترمینال جدا):

```bash
pnpm dev:api        # http://localhost:4000/api
pnpm dev:web        # http://localhost:3000
```

- اگر پورت ۳۰۰۰ یا ۸۳۳۳ پر بود، یک پشتهٔ دموی قدیمی روی ماشین است: `docker compose -f infra/docker-compose.demo.yml down`.
- **کد ورود (OTP) را از ترمینال API بخوانید.** پیامک جعلی است و این‌طور چاپ می‌شود: `[primary] OTP → 09121110001: کد ورود های مصالح: 12345`.
- پیامک‌های دیگر (تأیید/رد/یادآوری/بار جدید) هم در همین ترمینال می‌آیند، مثلاً `driver_rejected → 0912…: {"NAME":"حسن","DOC":"برگ سبز","REASON":"ناخوانا بودن"}`، و در جدول `SmsMessage` ثبت می‌شوند.
- برای دیدن/تغییر دیتابیس: `docker exec himasaleh-dev-postgres-1 psql -U hm -d hm` (نام کانتینر را با `docker ps` ببینید).
- **محدودیت ورود (فاز ۰):** یک مرورگر بیش از ۴ شمارهٔ جدید در ۱۰ دقیقه بدهد «ربات» حساب می‌شود و ۴ ساعت بسته می‌شود. بین شماره‌ها فاصله بیندازید یا این تنظیم را بالا ببرید (دستور SQL در بخش ۲.۴).

### ساخت کاربر کارشناس (staff)
رابطی برای ساخت کارشناس تا فاز ۳ نیست. یک‌بار این را اجرا کنید، بعد با موبایل `09120000001` از `/login?staff=1` (لینک «ورود مدیریت») با کد پیامکی وارد شوید:

```sql
INSERT INTO "User"(id,phone,"fullName",status,"updatedAt") VALUES ('staff1','09120000001','کارشناس آزمایشی','active',now());
INSERT INTO "UserRole"("userId",role) VALUES ('staff1','staff');
```

## ۲. حساب‌ها، داده و ابزارها

### ۲.۱ حساب‌های پیشنهادی
| نقش | موبایل | یادداشت |
|---|---|---|
| کارشناس | `09120000001` | ورود از `/login?staff=1` |
| راننده الف (مالک خودش) | `09121110001` | مسیر اصلی |
| راننده ب (مالک متفاوت) | `09121110002` | مالک شریک؛ موبایل مالک `09123334444` |
| راننده پ (مالک پدر) | `09121110003` | بستگان درجه یک |
| راننده ت | `09121110004` | رقابت برای قبول بار |

### ۲.۲ کد ملی (معتبر با رقم کنترل)
معتبر: `0012345679` · `0023456787` · `0034567895` · `0045678911` · `0056789122` · `0067891233` · `0078912342` · `0089123451`
نامعتبر: `0012345678` (رقم کنترل غلط) · `1111111111` (همه یکسان) · `12345` (کوتاه).
هر کد ملی فقط برای **یک** راننده ثبت می‌شود؛ برای هر راننده یکی بردارید.

### ۲.۳ فایل‌های آزمایشی
چند عکس JPG/PNG (یکی بزرگ، حدود ۸ مگابایت)، یک PDF کوچک، یک ویدیوی MP4 کوتاه (و یک بزرگ‌تر از ۱۰۰ مگابایت برای رد شدن)، یک فایل `.txt` و یک `.gif`. حد مجاز: عکس و PDF تا ۱۰ مگابایت، ویدیو تا ۱۰۰ مگابایت؛ انواع مجاز: JPEG، PNG، WebP، PDF، MP4، WebM، MOV.

### ۲.۴ دستورهای SQL کمکی

> روی سرور مستقر فقط اپس این‌ها را اجرا می‌کند و بخش ۸.۷ برای برگرداندن را رعایت کند.
```sql
-- تنظیمات (۳۰ ثانیه کش می‌شوند؛ ۳۰ ثانیه صبر کنید)
INSERT INTO "Setting"(key,value,"updatedAt") VALUES ('otp.botDistinctPhones','100',now()) ON CONFLICT (key) DO UPDATE SET value=EXCLUDED.value,"updatedAt"=now();
INSERT INTO "Setting"(key,value,"updatedAt") VALUES ('dispatch.offerTtlMin','1',now())     ON CONFLICT (key) DO UPDATE SET value=EXCLUDED.value,"updatedAt"=now();   -- مهلت قبول بار (دقیقه)
INSERT INTO "Setting"(key,value,"updatedAt") VALUES ('notify.newLoadSms.mode','"always"',now()) ON CONFLICT (key) DO UPDATE SET value=EXCLUDED.value,"updatedAt"=now(); -- "off" | "fallback" | "always"
INSERT INTO "Setting"(key,value,"updatedAt") VALUES ('notify.smsFallbackAfterSec','20',now()) ON CONFLICT (key) DO UPDATE SET value=EXCLUDED.value,"updatedAt"=now();
INSERT INTO "Setting"(key,value,"updatedAt") VALUES ('kyc.ownerVideoReminderHours','0',now()) ON CONFLICT (key) DO UPDATE SET value=EXCLUDED.value,"updatedAt"=now();
INSERT INTO "Setting"(key,value,"updatedAt") VALUES ('fee.driver.defaultBp','1000',now())  ON CONFLICT (key) DO UPDATE SET value=EXCLUDED.value,"updatedAt"=now();   -- سهم پلتفرم، basis point (۸۰۰ = ۸٪)

-- مشاهده
SELECT kind,"to",status,left(text,80) FROM "SmsMessage" ORDER BY "createdAt" DESC LIMIT 15;
SELECT type,channel,status,error,"ackedAt" FROM "NotificationLog" ORDER BY "createdAt" DESC LIMIT 15;
SELECT action,entity,"actorId","createdAt" FROM "AuditLog" ORDER BY "createdAt" DESC LIMIT 25;
SELECT account,"balanceRial" FROM "AccountBalance" ORDER BY account;
SELECT coalesce(sum("amountRial"),0) AS must_be_zero FROM "LedgerEntry";
SELECT id,status,step,"waybillNo","trackCode" FROM "Trip" ORDER BY "createdAt" DESC LIMIT 5;
SELECT step,"clientAt","serverAt","photoFileId" IS NOT NULL AS photo FROM "TripEvent" ORDER BY "serverAt" DESC LIMIT 10;

-- دستکاری برای سناریوهای خاص
UPDATE "DispatchOffer" SET "expiresAt"=now()-interval '1 minute' WHERE status='pending';       -- منقضی کردن پیشنهادها
UPDATE "Trip" SET status='cancelled' WHERE status IN ('assigned','loading','in_transit','arrived'); -- لغو سفر وسط راه
UPDATE "DriverProfile" SET status='blocked' WHERE "nationalId"='0012345679';                    -- مسدود کردن راننده
```

### ۲.۵ ابزار بار آزمایشی
در `/admin` (با کارشناس) دکمهٔ «ارسال بار آزمایشی» یک بار نمونه می‌سازد: «سیمان پرتلند تیپ ۲ — ۲۰۰ کیسه»، ۱۰ تن، کرایه **۸٬۵۰۰٬۰۰۰ تومان**، مبدا «مصالح فروشی البرز — کرج»، مقصد «کارگاه پروژه ونک»، ۴۲ کیلومتر. فقط به رانندگانِ **تاییدشدهٔ آنلاین («سر کارم»)** پیشنهاد می‌شود. با سهم ۸٪: پول راننده **۷٬۸۲۰٬۰۰۰ تومان** («۷ میلیون و ۸۲۰ هزار تومان») و سهم پلتفرم ۶۸۰٬۰۰۰ تومان.

## ۳. رفتارهایی که باگ نیستند (قبل از گزارش بخوانید)

- **ریفرش وسط ثبت‌نام قبل از «مرحلهٔ بعد» در مرحلهٔ ۲:** اطلاعات هنوز ذخیره نشده و پاک می‌شود. از مرحلهٔ ۲ به بعد پروفایل روی سرور است و بعد از ریفرش برمی‌گردد؛ ولی پیش‌نمایش عکس‌ها برنمی‌گردد (فقط «ارسال شده» و وضعیت).
- **ویرایش بعد از ارسال قفل است** (تا کارشناس رد کند).
- **پلاک** مثل طراحی و کامپوننت پلاک فاز ۰ چیده می‌شود (ترتیب ارقام در متن فارسی ممکن است برعکس به نظر برسد؛ این همان ساختار طراحی است).
- **نقشه** تایل OpenStreetMap است (کلید نشان نرسیده)؛ برای آدرس‌یابی اینترنت لازم است.
- در پنل راننده **شارژ کیف پول، بنر پاداش و معرفی** نیست (فاز ۲ و بعد). «پول من» فقط خواندنی است.
- **کارشناس رابط ساخت ندارد** (فاز ۳).
- **پیامک «بار جدید» و بقیه جعلی‌اند** (فقط لاگ). تست پیامک واقعی در بخش ۵ است.
- **اعلان فشاری جعلی است** (فقط لاگ). بدون اپ اندروید، اعلان به گوشی نمی‌رسد؛ پیامک جایگزین بر همین اساس رفتار می‌کند (بخش ۴.۱۱).
- تست‌های ابزار بار آزمایشی (`ENABLE_DEV_TOOLS`) روی تولید خاموش است.

### ۸.۳ نقش‌ها: تستر و اپس

تستر معمولاً به دیتابیس و سرور دسترسی ندارد؛ پس هر سناریویی که در متن «SQL»، «لاگ API» یا «تنظیمات» دارد **باید اپس انجام دهد** (یا ترتیب هماهنگ شود). دستورها (اپس، روی سرور):

```bash
cd /srv/himasaleh/infra
docker compose logs -f api                          # لاگ (JSON)
docker compose exec postgres psql -U hm -d hm       # دیتابیس (همان SQLهای بخش ۲.۴)
# تغییر تنظیم: SQL بخش ۲.۴ + ۳۰ ثانیه صبر (کش)
# تغییر متغیر محیطی: ویرایش .env سپس
docker compose up -d                                # api دوباره ساخته می‌شود
```

- **ساخت کارشناس:** SQL بخش ۱ (`staff1`) را اپس با **موبایل واقعیِ** یک عضو تیم اجرا کند (OTP واقعی می‌آید).
- **بار آزمایشی فقط برای راننده آزمایشی (بدون خطر برای رانندگان واقعی):** پس از روشن کردن `ENABLE_DEV_TOOLS=true` و `docker compose up -d`، با کوکی کارشناس از مرورگر (Console) یا Postman:
  ```
  POST https://himasaleh.ir/api/dev/test-trips
  {"driverId":"<شناسه DriverProfile راننده آزمایشی>"}
  ```
  شناسه: `SELECT id,"firstName" FROM "DriverProfile" WHERE "nationalId"='<کد ملی آزمایشی>';`. دکمهٔ `/admin` بدون این پارامتر به همه می‌فرستد؛ تا اصلاح نشده فقط وقتی استفاده شود که رانندهٔ واقعی آنلاین نیست.

### ۸.۴ حساب‌ها و داده

- **شماره‌های واقعی لازم است** (OTP واقعی پیامک می‌شود): حداقل ۴ شمارهٔ در اختیار تیم: کارشناس، راننده الف، ب (مالک متفاوت)، پ/ت. شمارهٔ مالک `09123334444` در سناریوها فقط یک مقدار ثبت‌شده است و نیازی به شمارهٔ واقعی ندارد.
- **کد ملی:** کدهای معتبرِ جعلی بخش ۲.۲ فرمت را رد می‌کنند، ولی اگر شاهکار خودکار روشن باشد «غیرهم‌خوان» برمی‌گردند (`matched:false`) که برای سناریوی منفی عالی است. برای سناریوی مثبت (`matched:true`) باید کد ملی و موبایل **واقعی خود تست‌کننده** باشد؛ داده بعد از تست حذف شود.
- **فایل‌ها:** تصویر نمونه، نه مدرک واقعی.
- لینک مالک در سرور `https://himasaleh.ir/o/…` است (نه `localhost`).

### ۸.۷ بعد از تست: برگرداندن و پاک‌سازی (اپس)

۱. `ENABLE_DEV_TOOLS` را خالی کنید و `docker compose up -d`؛ سپس `POST /api/dev/test-trips` باید ۴۰۴ بدهد.
۲. تنظیم‌هایی که دست خورده را حذف کنید تا پیش‌فرض برگردد:
   ```sql
   DELETE FROM "Setting" WHERE key IN ('dispatch.offerTtlMin','notify.newLoadSms.mode','notify.smsFallbackAfterSec','kyc.ownerVideoReminderHours','fee.driver.defaultBp','otp.botDistinctPhones');
   ```
   (۳۰ ثانیه تا اثر؛ مخصوصاً `fee.driver.defaultBp` که عدد مالی است.)
۳. کاربران و داده‌های آزمایشی (شماره‌های تست را جایگزین کنید). حذف کاربر راننده، پروفایل، مدارک، پیشنهادها، دستگاه‌ها و لاگ اعلان او را هم پاک می‌کند:
   ```sql
   DELETE FROM "User" WHERE phone IN ('<شماره‌های آزمایشی>');
   DELETE FROM "User" WHERE id='staff1';          -- کارشناس آزمایشی
   DELETE FROM "Trip" WHERE "isTest";             -- سفرهای آزمایشی
   DELETE FROM "SmsMessage" WHERE "to" IN ('<شماره‌های آزمایشی>');  -- اختیاری
   ```
۴. **دفتر کل پاک نمی‌شود** (طراحی‌شده). ردیف‌های آزمایشی را بشناسید و در گزارش‌های مالی کنار بگذارید:
   ```sql
   SELECT kind, count(*), sum(abs("amountRial")) FROM "LedgerTxn" t JOIN "LedgerEntry" e ON e."txnId"=t.id WHERE kind IN ('test_funding','trip_settlement') GROUP BY kind;
   ```
   حساب‌های `bank:main`، `escrow:trip:*`، `platform:revenue:fee` و `wallet:user:<راننده آزمایشی>` تا فاز ۳ فقط آزمایشی‌اند.
۵. فایل‌های آپلودشده در S3 (باکت خصوصی) پاک نمی‌شوند؛ ردیف `FileObject` بدون مالک می‌ماند. با ابزار S3 پیشوند `private/` در بازهٔ تاریخ تست را بررسی و حذف کنید (مدارک نمونه).
۶. لینک‌های مالک و توکن دستگاه جعلی (`Device`) با حذف کاربر پاک می‌شوند.

### ۸.۸ پیشنهاد

برای فاز ۲ که پرداخت و دفتر کل جدی‌تر می‌شود، یک **محیط آزمایش جداگانه** (دیتابیس، باکت و دامنهٔ فرعی، مثلاً `test.himasaleh.ir`) بسازیم. آن‌وقت تست روی سرور بدون آلودگی حسابداری، بدون خطر برای رانندگان واقعی و با اجازهٔ آزمودن سناریوهای خطرناک (BLK-SMS-07/08، INF-03/04) انجام می‌شود. این کار در CI/CD یک استقرار دوم و یک Caddy host است؛ اگر موافقید دستورش را می‌نویسم.
